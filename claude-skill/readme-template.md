## Section-Specific Guidance

### Badges
Only include badges if you can verify the information:
- License badge: only if LICENSE file exists
- Build badge: only if `.github/workflows/` or `.travis.yml` etc. exists
- npm/PyPI/crates badge: only if the package is published there
- Never invent a "version" badge or "coverage" badge without real data

### Installation Commands
- Match the exact package manager found in the repo (npm vs yarn vs pnpm, pip vs poetry vs uv)
- If there's a Makefile with a `make install` target, mention it
- Include the `git clone` step — don't assume readers know where to get the code

### Environment Variables
- Only document env vars that appear in the actual code (`.env.example`, `os.getenv`, `process.env`)
- Group related vars together with a comment explaining the group
- Indicate which are required vs optional

### Project Structure
- Annotate every top-level directory
- Go one level deeper for `src/` or `lib/` if it has meaningful sub-organization
- Skip generated folders (`node_modules/`, `dist/`, `__pycache__/`, `.git/`)

### Code Examples
- Use the actual package name / import path from the code
- Show realistic parameter values, not `foo` / `bar`
- If the project has an existing `examples/` folder, base examples on those
